# Content2Video INEMA

**🇧🇷 [Português](README.md) · 🇺🇸 [English](README.en.md) · 🇪🇸 [Español](README.es.md)**

One link goes in; an editable video comes out. The project reads a page, creates a script, storyboard, narration, captions, and motion design in HyperFrames, makes everything available for review, and only then renders the MP4.

The current default is a vertical video in Brazilian Portuguese, about 1 minute long with 30% tolerance (42–78 s), using the fixed voice `pt-BR-FranciscaNeural` and a minimum score of 8. The source page’s language does not change the voice: an English source still gets pt-BR narration unless explicitly requested otherwise.

[Open the visual guide](https://inematds.github.io/content2video/guia/en/) · [Project plan](docs/plano_content2video_inema.md)

Current version: `v1.06.00`. The history and planned updates are in the [ROADMAP](ROADMAP.md).

## Current architecture and providers

`v1.06.00` does not use an external generative video service. The current output is a programmable composition: the agent creates the script and scenes, HyperFrames arranges and animates the elements, and FFmpeg delivers the MP4.

| Component | Current responsibility | Generates AI clips? |
|---|---|---|
| Codex via OAuth or OpenAI API | Researches the source, plans the video, and creates or edits the script, HTML, scenes, and metadata | No |
| HyperFrames | Builds the timeline, animates, validates, opens the editor, and renders the composition | No; it renders the composition that was created |
| Edge TTS | Generates the narration, using `pt-BR-FranciscaNeural` for Brazilian Portuguese output | No |
| FFmpeg/FFprobe | Processes audio and video, verifies the file, and appends the CTA to the final MP4 | No |
| Local media | Provides images, videos, fonts, icons, and other files used by the scenes | Not by itself |

`AI_PROVIDER=codex` and `AI_PROVIDER=openai` choose how the production agent runs. This setting does not choose a clip generator and does not mean that the video is generated by OpenAI video models.

Generative clip or avatar providers such as HeyGen, Veo, Runway, Kling, or Sora are not integrated in this version. As a result, the interface does not yet offer a choice of video provider, model, clip duration, or credits for this type of service.

The current workflow mainly produces motion graphics, animated typography, diagrams, images, and local media. A project can use an existing video as media, but Content2Video does not request that clip from a generative provider.

### Planned evolution

A future version may allow users to choose, for each scene:

- HyperFrames composition and motion graphics;
- AI-generated clip;
- presenter or avatar;
- animated image;
- media uploaded or selected by the user.

This evolution should record the provider, model, duration, request status, estimated cost, and credits actually consumed for each scene. The integration should also retain a fallback path to HyperFrames or local media when a provider fails or is not selected.

## Prerequisites

- Node.js 22 or later;
- FFmpeg and FFprobe;
- `curl`, used by the `start.sh` health check;
- Codex CLI authenticated with `codex login` (default), or an OpenAI key configured in `.env`;
- internet access to read the URL and obtain HyperFrames on the first run.

Check the installation:

```bash
node --version
ffmpeg -version
codex --version
codex login status
```

## Installation

```bash
git clone https://github.com/inematds/content2video.git
cd content2video
cp .env.example .env
npm install
```

The actual `.env` file is never committed. The documented defaults are in `.env.example`. By default, `APP_HOST=0.0.0.0` and `PREVIEW_HOST=0.0.0.0` make the interface and editor available on all of the machine’s network interfaces.

## Use with the interface

Start the server in the background:

```bash
./start.sh
```

The script creates `.runtime/content2video.pid`, writes output to `.runtime/content2video.log`, and prevents a second instance from starting. To stop the server and the editors it opened:

```bash
./stop.sh
```

`stop.sh` checks that the PID belongs to this project before sending `SIGTERM`, waits up to 10 seconds for a normal shutdown, and uses `SIGKILL` only if the process does not respond. Runtime files in `.runtime/` are not committed.

On the same machine, open `http://127.0.0.1:3080`. From another computer, phone, or tablet on the local network, use the IP address of the machine running Content2Video, for example:

```text
http://192.168.2.99:3080
http://192.168.1.172:3080
```

List the available addresses with `hostname -I`. The address `0.0.0.0` is only the server’s listening address and should not be entered in the browser.

### Operation and diagnostics

```bash
# start
./start.sh

# check the process
cat .runtime/content2video.pid

# follow the log
tail -f .runtime/content2video.log

# stop
./stop.sh
```

`APP_PORT` still comes from `.env` (default `3080`). You can override parameters for a specific run:

```bash
APP_PORT=4080 ./start.sh
```

To restrict the interface to a specific address, set `APP_HOST` and `PREVIEW_HOST` before running the command or edit `.env`. The scripts prioritize variables provided in the terminal.

> Security: the interface does not have a login. Use it only on trusted networks and limit port `3080` to the LAN in your firewall. Do not forward this port on your router or expose the service directly to the internet.

You can also run it in the foreground, which is useful during development:

```bash
npm start
```

In the interface:

1. Paste the page or article link.
2. To guide the angle, fill in **Video objective**. This instruction supplements the link and defines the audience, focus, and message without replacing the source’s facts.
3. Choose **9:16 Vertical** (`1080 × 1920`) or **16:9 Horizontal** (`1920 × 1080`).
4. In the **Speaking style** dropdown, choose **Popular and simple**, **Natural conversation**, or **Technical and detailed**. The popular style uses short sentences and common words, and explains difficult terms with examples.
5. In the **Speech pace** dropdown, choose **Calm** (`-10%`), **Natural** (`+0%`), or **Fast** (`+12%`).
6. Leave **Add INEMA.CLUB CTA at the end** checked, or uncheck it to produce the video without the closing.
7. Choose the **Visual preset**. The default **Automatic — planner decides** analyzes the source, audience, and format to create a specific direction; the other presets apply defined visual guidelines. Use **Edit preset on another screen** to adjust the palette, typography, composition, movement, and media.
8. Click **Create visual direction**. The system researches the source and prepares only the brief, storyboard, and one pilot scene.
9. In the visual gate, review the image. Choose **Approve visual and produce**, **Edit preset**, or **Update pilot scene**. The voice and full set of scenes are generated only after approval.
10. During production, the status shows the current activity and keeps the editor, prompt editing, copy, and render actions locked to prevent opening or changing an incomplete composition.
11. When production finishes without an MP4, the status shows **Awaiting review**: use **Open editor** or **Edit with prompt**.
12. Use **Create copy** when you want to adapt a version without changing the original project.
13. Click **Approve and render**, then download the MP4 from the project card.
14. When the status changes to **Ready to watch**, the play button appears on the cover and opens the final MP4.

Both choices are recorded in `BRIEF.md` and `meta.json` as `conversation_style`, `speech_pace`, and `voice_rate` before audio generation. Edits and regenerations preserve the project’s style and pace.

### Phases, resuming, and canceling

Each job shows its type, format, total time, current phase, and time spent on each step. The active step’s duration keeps counting; completed steps retain their final time. Generation, copying, prompt editing, and rendering have their own timelines. While a job is queued or running, the **Cancel** button stops the Codex, HyperFrames, browser, and FFmpeg processes associated with it.

The interface uses the generator’s latest activity to avoid announcing validation while scenes are still being built. A job is complete only when `index.html` contains a finished composition; an empty initial file does not unlock the editor.

Canceling preserves the files produced up to that point for inspection or resuming. The job history stays in memory during the current server session; restarting the application clears the job list, but projects and files remain in `output/content2video/`.

When a render fails or is canceled, valid files remain as checkpoints in `.runtime/render-staging/`. During the same server session, **Continue where you left off** reuses these files and skips validation, rendering, or CTA steps that have already been completed. Skipped phases appear as **reused** and do not get a new duration.

This is the default behavior: continuing reuses what is already ready. Use **Redo full render** only when you want to discard that attempt’s checkpoint and run all phases again. After the MP4 is successfully saved to `output/content2video/<projeto>/renders/`, temporary checkpoints are removed.

### Edit visually or with a prompt

- The play button appears on the cover only when an MP4 is ready, and plays the final video directly.
- **Open editor** opens HyperFrames Studio for review and direct editing.
- **Edit with prompt** changes the current project. Describe what you want to change and, preferably, what should be preserved.
- In **Edit with prompt**, the **Continue where you left off** shortcut completes incomplete material, preserves what is already correct, fixes validation, and prepares snapshots without rendering.
- **Create copy** duplicates the project, removes old renders from the copy, and applies the instruction only to the new folder. The copy gets a name such as `<projeto>-copia` or `<projeto>-copia-2`.

Example instruction:

```text
Remove the scene about prices, keep the current voice and colors,
change the final CTA, and make the pacing more direct.
```

Edits and copies accept a format change and the CTA option in the same panel. The agent updates the composition, brief, and metadata, keeps `pt-BR-FranciscaNeural` for Brazilian output, and runs validation before making it available for review.

### Prompt library for editing

Copy a block into **Video objective** when creating a direction or into **Edit with prompt** for an existing video. In the objective field, it guides the new production; in the editor, it changes the current project.

**Change only the visual direction**

```text
Change only the visual direction. Use a premium editorial aesthetic, with a dark background,
strong typography, one dominant idea per frame, and short movements. Preserve the facts,
script, duration, voice, and CTA. Avoid neon, glassmorphism, and excessive cards.
```

**Improve readability without redesigning**

```text
Preserve the current visual identity. Improve contrast, hierarchy, and breathing room.
Break titles at natural points, keep them within the safe area, and allow enough time to read.
Do not change the script, narration, images, or duration unless necessary.
```

**Scientific editorial**

```text
Use a scientific editorial direction: clear diagrams, data with visible sources, a restrained palette,
and precise typography. Explain the cause and effect relationship visually. Avoid decorative images,
unexplained jargon, and the look of a corporate presentation.
```

**Technology without neon**

```text
Create a mature technology aesthetic, with deep blue, white, and a single accent.
Use real interfaces, flows, and product details. Do not use neon, futuristic grids,
random code, generic robots, or decorative glow.
```

**Make data the protagonist**

```text
Turn the key numbers into a visual narrative. Show context, comparison,
and consequences; one metric at a time. Preserve accuracy and write the source on screen.
Avoid 3D charts, misleading axes, and counters without context.
```

**Simplify the movement**

```text
Reduce movement to what is needed to direct attention. Use short entrances, pauses
for reading, and transitions motivated by the content. Preserve the layout and identity.
Remove continuous floating, decorative parallax, and simultaneous animations.
```

**Strengthen the opening hook**

```text
Rewrite only the first 5 seconds to open with the article’s most concrete consequence.
Make the image prove the statement. Preserve the facts, voice, style, and rest of the video.
Do not use a generic question or sensational promise.
```

**Audit the safe area**

```text
Validate all headlines at the beginning, peak, and end of each animation after fonts
have loaded. In 9:16, keep the maximum width at 85% and side margins at 7.5%.
Break lines by meaning before reducing the font size. Correct any pixel outside the safe area.
```

**Adapt the format correctly**

```text
Adapt this version to 9:16. Recompose each scene for the new frame; do not just crop
or scale the horizontal layout. Preserve the script, voice, identity, and reading time.
Reposition images and data to take advantage of vertical reading.
```

**Reuse another project’s style**

```text
Use the project <nome-do-projeto> as a visual reference: palette, typography, density,
image treatment, and movement pace. Do not copy content or scene structure.
Preserve this video’s script and voice, and record the reference in the brief.
```

### Automatic CTA

**Add INEMA.CLUB CTA at the end** is checked by default when creating a video, editing with a prompt, and creating copies. The choice is saved as `include_cta` in the project’s `meta.json` and appears on the card as **CTA at the end** or **No CTA**.

When you click **Approve and render**, the system renders the editable composition and, when the option is active, appends a 5.5-second closing suited to the selected format. The CTA is not inserted into the editable scenes; it is joined only to the final MP4. This means it can be turned on or off in a future edit without changing the video content.

The files reused by the render are located at:

```text
output/content2video/inema-club-cta/renders/inema-club-cta.mp4
output/content2video/inema-club-cta/renders/inema-club-cta-16x9.mp4
```

During rendering, the interface separately shows **Rendering video** and **Adding CTA**. If the CTA is unchecked, this step is skipped.

The `npm run video:render -- <projeto>` command also respects `include_cta`. The direct `npx hyperframes render` command produces only the composition and does not automatically append the CTA.

The interface does not require its own login. It is designed for local or private network use; do not expose it directly to the internet without adding authentication and HTTPS.

## Use from the terminal without the interface

See the available commands:

```bash
npm run video -- --help
```

Create a project from a URL. The final, optional argument sets the folder name:

```bash
npm run video:create -- https://www.inema.club/ inema-club-promo
```

The command creates `output/content2video/inema-club-promo/`, generates the editable material, and validates the composition, but does not render automatically. Then:

```bash
npm run video:list
npm run video:check -- inema-club-promo
npm run video:preview -- inema-club-promo
npm run video:render -- inema-club-promo
```

The final MP4 is located at:

```text
output/content2video/<nome-do-projeto>/renders/<nome-do-projeto>.mp4
```

You can also run HyperFrames directly inside any video project:

```bash
cd output/content2video/inema-club-promo
npx --yes hyperframes@0.8.20 check
npx --yes hyperframes@0.8.20 preview
npx --yes hyperframes@0.8.20 render --quality high --output renders/inema-club-promo.mp4
```

## Subscription OAuth or API

The default reuses the OAuth session already connected in Codex CLI:

```dotenv
AI_PROVIDER=codex
```

Log in once on the computer:

```bash
codex login
```

To use the OpenAI API, change only the local `.env` file:

```dotenv
# AI_PROVIDER=codex
AI_PROVIDER=openai
OPENAI_API_KEY=sk-...
# OPENAI_MODEL=
```

Never send the key to Git. `.gitignore` already excludes `.env` and local variants.

These two options control the agent that builds the project. Neither activates video clip generation in `v1.06.00`.

## Security and publishing

- do not commit `.env`, tokens, cookies, or credentials;
- review usage rights for media captured from the source page;
- keep the interface restricted to a trusted network while it has no login;
- check headlines in the safe area and listen to the narration before the final render.

## Versioning

The displayed version follows the `vMAJOR.FEATURE.FIX` format:

- `v1.01.00`: new feature delivered; increments FEATURE and resets FIX to `00`;
- `v1.01.01`: bug fix with no new feature; increments only FIX;
- `v2.00.00`: major or incompatible change; increments MAJOR and resets the other fields.

The FEATURE and FIX fields are displayed with two digits, but remain numerically compatible with `package.json` (`1.1.1`, for example).
